## Packaging Impact

The downstream metadata draft currently keeps:

```textproto
subsets: "latin"
subsets: "latin-ext"
subsets: "menu"
subsets: "vietnamese"
```

This is intentional because the font now clears the local Google Fonts support
thresholds for both declared broad subsets:

- `latin-ext`: 308/1144 codepoints, threshold requires 229.
- `vietnamese`: 109/115 codepoints, threshold requires 58.

The remaining `unreachable_subsetting` WARN is about encoded combining marks,
spacing modifier marks, and dotted circle that are not covered by the declared
GF subsets. Do not narrow the metadata scope just to reduce WARN count; that
would strand many already-encoded Latin Extended and Vietnamese codepoints.
Before the final package, choose one of these paths:

1. Keep the broader subset declarations and review the remaining
   `unreachable_subsetting` WARN with Google Fonts if needed.
2. Deliberately defer broader Latin Extended/Vietnamese support by unencoding
   or removing out-of-scope codepoints, then rerun the full Fontspector profile
   to prove no `glyph_coverage`, dotted-circle, or shaping regression appears.

Current mechanical coverage additions:

- U+02BC MODIFIER LETTER APOSTROPHE is present in all active UFO masters as
  `uni02BC`, componentized from `quoteright`, because package-context
  Fontspector sample-text checks need it for languages implied by the current
  Latin coverage.
- `Tbar`, `tbar`, `Gstroke`, `gstroke`, `Ezh`, `ezh`, `Ezhcaron`,
  `ezhcaron`, and `longs` are present as component-based review glyphs. This
  cleared the release Fontspector auxiliary shape-language WARN, but the
  drawings still need human proof review before final submission.
- Vietnamese coverage glyphs are present as component-based review glyphs
  generated by `scripts/add_vietnamese_components.py`. The build now reports
  `GF_Latin_Vietnamese 100%`, but the generated horn, hook-above, dot-below,
  and stacked-accent constructions need human proof review.
- Latin Extended coverage glyphs are present as component-based review glyphs
  generated by `scripts/add_decomposable_latin_ext_components.py`. The script
  adds only decomposable glyphs whose bases and marks already exist, and skips
  boundary-crossing composites that would make Google Fonts package-context QA
  expect broader Pinyin, PriAfrican, or Aleut support.

The deferral path is risky: an earlier cmap cleanup probe showed that removing
required support codepoints can create new Google Fonts failures. Test any such
change against the full `make test` gate before adopting it.
